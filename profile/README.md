<p>掉线那一刻最容易做错的决定，是"先放几天看看能不能自己缓过来"。短期掉线里有相当一部分确实是网络抖动，等十分钟就恢复；但也有一部分是出口地址已经被标记，越等越糟，因为同一个地址还在被你的其他账号使用。这篇不讨论玄学，只给判断节点：什么情况下等，什么情况下立刻换线，换的时候按什么顺序动，以及并发到底该怎么算才不浪费钱。</p>

<h2>一、第一步不是处理，是分类</h2>
<p>看到页面打不开或者弹出验证，先别急着重启、清缓存、换浏览器。这些动作会把现场证据破坏掉，之后就无法判断到底哪一层出的问题。正确的做法是先看三个信号。</p>
<h3>看错误形态：超时、403 还是验证页</h3>
<p>连接超时、TLS 握手失败属于网络层，通常是上游链路问题；明确的 403 或者页面直接跳转到验证，属于地址或账号侧；能进页面但要求重新登录，属于会话层。三类问题的处置完全不同，混在一起处理只会白折腾。</p>
<h3>看影响范围：一个号还是同线全部</h3>
<p>如果同一条线路上挂着的三个号同时出问题，基本可以判定是线路侧；只有一个号异常，其他号正常，那更可能是这个号本身的状态。这一步用台账就能查，前提是你事前记了"哪条线服务哪些号"。</p>
<h3>看可复现性：换一条线还出不出</h3>
<p>把异常账号临时切到另一条已验证干净的线上跑五分钟。如果恢复正常，问题在原线路；如果照样异常，问题在账号。这个动作成本很低，但要记得切回去之前先把原线路标记为"待复查"，别让其他号继续往上挂。</p>

<h2>二、决定"养还是换"的四个条件</h2>
<p>分类清楚之后，决策其实只剩一两个变量。下面四个条件里，只要命中前两条中的任意一条，就不建议再养。</p>
<h3>条件一：这条线近期是否反复出问题</h3>
<p>台账里三十天内同一条线出现两次以上验证或 403，就当作已经污染。反复出问题说明不是偶发，继续用只会把更多账号拖进同一个记录里。判断标准要写在台账上，避免凭印象。</p>
<h3>条件二：这个号是否涉及订阅或支付</h3>
<p>涉及付费的账号，处置要更保守：宁可换一条新线重登，也不要在原地址上反复尝试。反复失败容易让账号进入更长的观察期，恢复成本远高于一条线路的月费。</p>
<h3>条件三：订阅还剩多少天，手上有无备用线</h3>
<p>这两项决定动作的果断程度。订阅还有二十多天，值得花时间救回来；只剩两三天，直接换新环境重新开始，时间成本更低。有备用干净地址，动作可以立刻做；没有备用线，就得先采购，中间这几天原账号保持静默，不要继续试探。</p>

<h2>三、换出口的动作顺序</h2>
<img src="/tp.png" alt="Claude 账号掉线后判断养号还是更换住宅出口的处理顺序">
<p>顺序错了会白干。很多人先清缓存再换线，结果换了线还是异常，因为配置文件里残留的会话状态没清。正确顺序是先隔离、再换线、最后登录。</p>
<h3>先把旧环境冻住</h3>
<p>把异常账号对应的浏览器配置文件整个复制一份留档，然后停用原配置文件，不再打开。留档是为了以后回溯"这个号最后一次正常是什么状态"，不是为了继续用。</p>
<h3>新线先验证再挂号</h3>
<p>新地址到手，先只做验证：查 whois 机构字段、查 ASN 类型、访问查询 IP 的页面确认地区。三项都符合预期，再新建一个干净的浏览器配置文件登录。不要在旧配置文件里改代理设置，那等于在污染的会话上换地址。</p>
<h3>登录后先做低风险动作</h3>
<p>登录成功不要立刻跑大批量任务。先做几次普通对话、看看设置页、确认订阅状态显示正常，观察半小时再逐步加量。这个节奏不是玄学，是给账号一个可解释的过渡。</p>

<h2>四、并发占用怎么算才不浪费</h2>
<p>"并发占用多少算多少"这句话容易被理解成能开多少开多少，实际相反：算清楚占用，才知道该买几条线。</p>
<h3>按同时活跃的号算，不按账号总数算</h3>
<p>十个号里同一时刻真正在操作的通常只有三到五个。线路数按峰值活跃数配，再留一条备用即可。按总数配线，大部分线路一天里大部分时间是闲着的，月费白花。</p>
<h3>一条线同时只挂一个登录态</h3>
<p>这里的"一个"指同一时刻只有一个账号用这条线。轮班使用可以，但同时登录两个号不行。要做到这一点，台账里给每条线加一列"当前占用账号"，交接时先看这一列。</p>
<h3>留一条同地区的冷备用</h3>
<p>备用线不登录、不常开，只在主线路异常时启用。它的作用是让换线动作在十分钟内完成，而不是当天再去下单。成本上相当于多买一份保险，价格区间通常在数十元到两百元每月（仅供参考）。</p>

<h2>常见问答</h2>
<h3>掉线后放几天再登录，会不会更容易恢复？</h3>
<p>答：要看掉线原因。如果是地址被标记，静默几天对地址本身没有帮助，换线更快；如果是行为触发的人工复核，静默确实有意义。判断方法就是前面说的换线测试，五分钟就能分辨。</p>
<h3>同一个浏览器配置文件能不能换一条线继续用？</h3>
<p>答：技术上可以，但不建议。旧配置文件里留着上一次的会话痕迹，换地址后这些痕迹会和新地址一起被读到，反而增加不一致。新建配置文件、重新登录，成本只是多花几分钟。</p>
<h3>并发占满之后，多加一条线能提升多少？</h3>
<p>答：提升的是"同时可操作的账号数"，不是速度。线路本身不决定回复快慢，决定的是能不能让更多账号各自有独立环境。按峰值活跃数配线即可，多配不会更快。</p>
<h3>怎么判断一条新线是不是真的干净？</h3>
<p>答：三项自查：whois 机构名指向当地运营商、ASN 类型不是托管、用公开情报页看该段近期没有被大量标注。三项都过，再用一个不重要的号试登一次，确认无额外验证后再挂正式账号。</p>
